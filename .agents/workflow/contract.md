# Workflow report contract (v1)

Tools use Node.js built-ins only. Run from repository root. Keep generated task artifacts in the existing `docs/human/task record/<TASK>/` location when requested. Do not overwrite synced `sources/` files.

Common fields: `schemaVersion: 1`, `kind: "plan" | "verification"`, `project`, `taskId`, `repository: "owner/repo"`, `revision` (40 hex Git SHA), `title`, `sources: [{path, sha256, excerpt}]`. Hash source bytes, record actual inspected content and commit, and do not imply the excerpt is the entire file. Reports are normalized and fingerprinted by the renderer. SHA-256 fingerprints bind exports to exact report contents, not user identity.

Plan: `versions: [{id, summary, mockups: [{title, path}], decisions: [{id,title,proposal,reason,impact,requiresExplicitApproval}], acceptance: [string]}]`. Version IDs and decision IDs are unique within their scopes; latest array entry is current. Draft paths may be relative images or HTTPS images. No active HTML is accepted. Proposal approvals cannot transfer across versions. Approving a service-policy decision means that specific proposal, never unrelated permission.

Verification: `runs: [{id,role: "developer" | "independent-qa",actor,revision,executedAt,environment:{url,viewport,build},checks:[{id,title,result: "passed" | "failed" | "not-run",observed,evidence:[{kind:"screenshot" | "command" | "source",path?,command?,capturedAt?}],issueIds:[string]}],issues:[{id,title,severity:"minor" | "major" | "critical",location,actual,expected,steps:[string]}]}]`. Every executed check needs evidence. Screenshots need path/time; command evidence needs command. Source evidence alone is not runtime evidence. Independent QA requires a different actor and matching build/revision; record limitations as not-run. IDs within runs are unique; current runs must agree on any shared issue ID.

The current-revision latest developer and QA runs drive completion. Both need runtime checks and actual screenshot evidence. Any not-run, major/critical issue, or failed check without only minor linked issues is blocked. Otherwise result is `complete` or `conditional-complete`. Past failures stay in the history. Do not hide a missing acceptance criterion by omitting its check: agents must map the actual PRD criteria to the supplied checks.

Human exports contain `kind: plan-review | verification-review`, report identity/fingerprint, `round`, `reviewedAt`, exact `versionId` or `runIds`, decision values and `history`. Plan decisions use `approved | revise | hold`; verification uses `approved | conditional-complete | revise | hold`. Browser review states start at hold, with no pre-approved choices. Each explicit save/download creates a new immutable round; history can be imported only for the same report fingerprint. Export is blocked on a storage failure until recovery. Human decisions never modify evidence or computed readiness.

Verification conditional-complete exports explicitly list `acceptedIssueIds`; these must be current minor issues, with every current issue accepted. Issue Manager rejects any mismatched identity, stale run, missing acceptance, invalid round or non-conditional verdict. Queue entries contain a stable marker `<!-- petsns-issue:<sha256> -->`. Registry ledger entries record key, URL, disposition and time; repeated registration of one key is idempotent, conflicting URLs are rejected. `prepare` never writes to GitHub. Use connector tools for real issue creation with full pagination/semantic checks.
