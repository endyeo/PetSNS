# T29 배포 기준 반려동물 DB 연결

작성일: 2026년 10월 10일. 상태: 구현·원격 API·release 산출물 검증 완료. 웹 배포는 사용자의 요청에 따라 실행하지 않았다.

후속 [T30](t30-supabase-memory-days.md)에서 하루 기록의 서버 저장·삭제와 반려동물 삭제 제한 FK를 추가했다. 아래의 일기 작성 제한은 T29 수행 당시의 범위이며 현재 동작은 T30을 따른다.

## 목표와 범위

온라인 빌드에서 본인 반려동물의 이름·품종·생일·Day 0를 실제 Supabase DB에 저장하고 다른 실행 환경에서도 같은 계정으로 조회한다. T27의 DB/RLS와 T28의 Auth를 사용한다. 기존 로컬 기록은 이전하거나 소유자를 변경하지 않는다.

사진 업로드, 추억·일기·모임·채팅 DB 연결, 회원가입, 공개 호스팅은 별도 범위다. 온라인 반려동물에 대한 추억·모임의 로컬 작성은 서버 참조 제약을 구현할 때까지 차단한다. 기존 로컬 데모는 유지한다.

## 확정한 동작

- 로그인·세션 복원 후 본인 사용자 프로필을 확인하고, 없으면 최초 1회 생성한다. 표시 이름은 DB 프로필에서 읽는다. 본인 반려동물 조회까지 성공해야 홈으로 진입한다. 서버 실패를 로컬 데이터로 대체하지 않는다.
- 반려동물 조회·생성·수정·삭제와 Day 0 저장은 실제 사용자 세션의 REST API와 기존 RLS를 사용한다. ID와 소유자는 서버가 결정하며 수정 요청에 소유자 변경을 포함하지 않는다.
- 변경한 필드만 서버에 보낸다. 프로필 수정이 다른 실행 환경에서 바뀐 Day 0를 덮어쓰지 않는다. 동시에 같은 필드를 수정하면 마지막 서버 저장이 적용된다. 자동 실시간 동기화는 이번 범위가 아니며 재로그인·재실행으로 다시 조회한다.
- 서버가 응답한 뒤 화면 목록을 갱신한다. 실패하면 기존 목록을 유지하고 재시도 안내를 표시한다. 중복 저장은 거부하며 로그아웃·계정 변경 후 도착한 응답을 다른 계정의 목록에 적용하지 않는다.
- 설정 포함 실행·profile/release 빌드·localhost 외 웹 호스트에서는 온라인 인증과 DB를 사용한다. 설정 없는 로컬 debug 실행만 데모를 제공한다. 설정 누락·오류는 시작을 차단한다. 웹 빌드 스크립트는 URL과 Publishable Key만 허용하고 비공개 키·계정 파일·추가 설정을 거부한다.
- 로컬 JSON에는 온라인 반려동물을 쓰지 않는다. 같은 이메일이라는 이유로 로컬 동물을 자동 이전하지 않는다.
- 프로필 사진 업로드는 준비 중으로 표시하고 온라인 사진 선택을 숨긴다. DB에 이미지 바이너리를 넣지 않는다.
- 이름 1~60자, 품종 80자 이하, 생일·Day 0는 1990년부터 KST 오늘까지 허용한다. 기존 DB의 길이·날짜·Day 0 쌍 제약도 적용한다.
- 연결된 기록이 있는 반려동물은 삭제를 차단한다. 현재 기기의 기존 추억·일기·참여 참조는 앱에서 확인한다. 신규 온라인 연결 기록 작성은 차단하므로 다른 기기에서 숨은 로컬 참조를 만들지 않는다. 후속 기록 DB에는 반드시 삭제 제한 FK를 적용한다. 기존 타 기기에 저장된 로컬 기록을 서버에서 검색하거나 보호하는 기능은 이번 범위가 아니다.
- 반려동물이 남은 사용자 프로필 삭제는 기존 서버 FK가 차단한다. 계정 삭제 UI는 구현하지 않는다.

## 완료 기준과 재현

1. 실제 계정 A가 앱 저장소를 통해 생성·수정한 동물을 독립된 Supabase 클라이언트와 새 저장소에서 조회한다. 생일과 Day 0가 유지되어야 한다.
2. B의 앱 목록에 A의 동물이 없어야 한다. B의 직접 읽기·수정·삭제·소유자 위조 생성도 서버에서 거부하거나 0행을 반환해야 한다.
3. 연결 기록이 없는 동물 삭제 후 새 조회에서도 없어야 한다. 연결된 로컬 기록이 있으면 앱 삭제 요청을 보내지 않아야 한다. 자식 기록 작성 차단을 확인한다.
4. 서버 실패·중복 저장·계정 변경 중 응답 도착에서 잘못된 홈 진입이나 목록 변경이 없어야 한다.
5. 온라인 CRUD 후 기존 로컬 JSON이 그대로여야 한다. Flutter 회귀 검사·정적 분석·설정 포함 웹 release 빌드가 통과해야 한다.
6. 실제 웹 배포는 하지 않는다. 배포 도메인의 브라우저 저장소·새로고침 검증은 호스팅 이후 별도 수행한다. 현재 완료 판정은 원격 DB/API 검사와 release 산출물 검증으로 한다.

## 수행 기록

- 반려동물 REST 저장소와 앱 연결, 서버 조회 완료 후 홈 진입, 계정별 메모리 목록, Day 0 저장을 구현했다.
- 서버 참조가 없는 로컬 자식 기록 작성을 온라인 모드에서 차단하고 사진 업로드 준비 안내를 추가했다.
- [단위 검사](../../test/supabase_pet_test.dart) **8개**, [실제 계정 검사](../../test/supabase_pet_live_test.dart) **21개 조건** 통과. 실제 검사에서는 앱 저장소 CRUD·독립 클라이언트 재조회·A/B 직접 API 권한·미인증 조회 거부·프로필 FK 삭제 제한·로컬 원본 보존을 확인했다. 실제 브라우저를 두 대 사용한 E2E 검사는 아니다.
- 전체 Flutter 회귀 검사 **103개 통과, 선택 실행 4개 건너뜀**. 실제 반려동물 검사는 위와 같이 별도 실행했다. 다른 선택 실행 검사는 이번 단계에서 실행하지 않았다.
- 비 HTTPS URL, 비공개 키, 테스트 비밀번호 추가 설정, 인증 정보 포함 URL의 **4가지 빌드 설정**을 Flutter 실행 전에 거부했다.
- 최종 `flutter analyze`에서 오류·경고 없음. 설정 검사를 거친 `scripts/build-web.ps1`의 웹 release 빌드 통과. 웹 텍스트 산출물 **14개**에서 실제 테스트 이메일·비밀번호 4개 값이 포함되지 않았고, 실제 프로젝트 URL·Publishable Key는 포함된 것을 확인했다. 테스트 계정 파일과 빌드 산출물은 Git 제외 상태다.
- 이번 검사가 만든 동물과 프로필을 사용자 권한 API로 정리했다. 종료 후 원격 DB의 프로필·동물은 각각 **0행**이었다. Auth 개발 계정은 유지했다. DB 스키마·기존 RLS는 변경하지 않았다.
- 증거 로그는 Git 제외된 `build/db-verification/pet-live-results.log`, `pet-regression-results.log`, `pet-web-build-results.log`에 기록한다. 공개 배포·배포 도메인 검증은 사용자의 요청에 따라 실행하지 않는다.

## 재현 명령

개발 프로젝트 URL·Publishable Key는 `config/supabase.local.json`, 전용 A·B 계정은 Git 제외된 `config/supabase.test.local.json`에 둔다. 계정 파일을 앱 빌드 설정이나 Flutter 자산으로 추가하지 않는다.

```powershell
flutter test
flutter analyze
./scripts/build-web.ps1
$env:PET_SNS_RUN_PETS_LIVE = '1'
try {
  flutter test test/supabase_pet_live_test.dart --dart-define-from-file=config/supabase.local.json --reporter expanded
} finally {
  Remove-Item Env:PET_SNS_RUN_PETS_LIVE
}
```

실제 검사 성공 출력은 `PASS: 21 assertions; real app CRUD, two users, independent clients, RLS, cleanup, local preservation.`이다. 전용 계정에 기존 동물이 있으면 테스트를 중단하며 임의로 삭제하지 않는다. 생성 요청이 서버에 반영된 직후 응답이 끊기면 테스트가 ID를 알 수 없는 기록은 자동 삭제하지 않는다.
