서비스의 중심

보호자가 반려동물 사진을 날짜와 사건에 맞춰 남기고 다시 찾아보는 경험이 핵심입니다. 여기에 지역의 일회성 약속을 통해 다른 보호자·반려동물과 함께 활동할 기회를 제공합니다.

참고한 서비스 방향: Instagram의 사진 공유 경험, 쑥쑥찰칵의 성장 기록 경험, 당근의 지역 연결 경험. 각 서비스의 현재 기능을 그대로 재현한다는 의미는 아닙니다.

02

사용자와 이용 상황

아래는 팀이 예상하는 이용 시나리오입니다. 사용자 조사 결과로 확정된 사실은 아닙니다. 현재는 사용자 수요 검증 단계를 별도로 진행하지 않고 개발 기획을 구체화하기로 했습니다.

SCENE A · 추억을 남기는 보호자

“이 사진이 언제였는지, 어떤 날이었는지 기억하고 싶어요.”

사진에 날짜와 메모를 붙여 기록하고, 반려동물의 생일이나 입양일 같은 특별한 날의 추억을 다시 찾아봅니다.

필요한 경험: 반려동물 등록 → 기록 작성 → 기록 정리·조회
SCENE B · 함께 활동하고 싶은 보호자

“이번 주말에 함께 산책할 친구를 찾고 싶어요.”

날짜·장소·참가 조건에 맞는 약속을 찾고, 자신의 반려동물과 참가합니다. 참가자들은 약속 채팅방에서 소통합니다.

필요한 경험: 약속 탐색 → 조건 확인 → 즉시 참가 → 채팅
03

사용 흐름

화면 설계 전, 사용자가 목적을 이루는 순서를 정리한 초안입니다.

내 반려동물의 추억 기록 흐름 초안

  1. 1로그인
  2. 2반려동물 등록·선택
  3. 3사진·날짜·메모 입력
  4. 4기록 저장
  5. 5타임라인에서 조회

일회성 약속에 참가 MVP 방향

  1. 1약속 모집 목록·상세 보기
  2. 2마감·잔여 정원 확인
  3. 3동반 마릿수 입력
  4. 4즉시 참가
  5. 5이번 참가 이후 채팅 보기

일회성 약속을 개설 입력 구성 초안

  1. 1활동·장소·일정 입력
  2. 2정원·참가 마감 설정
  3. 3동반 마릿수 입력
  4. 4생성과 동시에 자동 참가
현재 약속에 공동 사진 공유 기능은 포함하지 않습니다. 모임 사진을 개인 타임라인에 자동 연결하거나 공동 앨범을 생성하는 기능도 확정 범위에 포함하지 않습니다.

05

약속·채팅 규칙

개설 시 일정·정원·참가 마감을 정하고, 이후에는 모두가 동일한 참가자 권한으로 이용합니다.

  • 참가 조건 확정
    종·품종으로 참가를 제한하지 않습니다. 취소되지 않은 약속에 참가 마감 전이고 정원이 남아 있으면 즉시 참가할 수 있습니다.
  • 정원·동반 정보 확정
    계정 1개를 참가자 1명으로 계산하며 개설자도 정원에 포함합니다. 한 참가자가 여러 반려동물을 동반할 수 있고, 반려동물 수는 사람 정원을 차지하지 않습니다. 동반 마릿수는 숫자를 직접 입력하거나 ± 버튼으로 조절합니다.
  • 참가 마감 확정
    개설자가 생성 시 마감 시각을 설정합니다. 마감 전이고 정원이 남아 있으면 즉시 참가할 수 있고, 마감 시각에 도달하면 신규 참가·재참가를 막습니다.
  • 개설자 권한 확정
    개설자는 동반 마릿수를 입력하고 약속 생성과 동시에 참가자로 등록됩니다. 이후 개설자도 일반 참가자와 동일합니다. 참가 승인·거절, 강퇴, 공지, 약속 수정·취소 권한을 별도로 주지 않습니다. 본인은 나갈 수 있습니다.
  • 탈퇴·재참가 확정
    약속에서 나간 사람은 해당 채팅을 볼 수 없습니다. 메시지 전송 권한도 참가 상태와 연결해 차단하는 것으로 구현 초안을 잡습니다. 마감 전이고 정원이 남아 있으면 재참가할 수 있습니다. 전원 탈퇴로 취소된 약속에는 재참가할 수 없습니다.
  • 대화 조회 범위 확정
    최초 참가와 재참가 모두 현재 참가 시점 이후의 메시지만 볼 수 있습니다. 재참가하면 조회 기준 시점을 새로 설정하므로, 과거 참가 당시 보았던 메시지도 다시 보여주지 않습니다. 같은 참가 상태에서 새로고침·재접속한 경우에는 기준 시점을 변경하지 않습니다.
  • 전원 탈퇴 확정
    마지막 참가자가 나가면 약속은 자동 취소됩니다. 채팅방은 사용자에게서 사라지고 더 이상 접근할 수 없습니다. 내부 데이터의 실제 삭제·보관 정책은 미정입니다.
  • 채팅 이용 기간 확정
    약속 날짜의 다음날 23:59까지 이용하고, 그다음 날 00시에 폐쇄합니다. 모든 시각은 한국 시간(Asia/Seoul) 기준입니다. 예: 10월 5일 약속은 10월 6일까지 이용하고 10월 7일 00시에 닫힙니다. 약속 종료 시각 입력과 ‘종료 후 24시간’ 계산은 사용하지 않습니다.
  • 폐쇄 예정 안내 확정
    채팅방이 닫힌다는 안내를 시스템이 강제로 표시합니다. 개설자가 작성하는 공지가 아닙니다. 표시 시점·방식·반복 여부와 접속하지 않은 참가자에게 보여줄 방식은 미정입니다.

06

결정이 필요한 사항

이 항목들은 구현 담당자가 임의로 확정할 내용이 아닙니다. 관련 기능 개발 전에 팀이 첫 버전의 기준을 정하고 기획서에 반영합니다.

  1. 채팅 폐쇄 안내·데이터 보관

    강제 안내의 표시 시점과 방식, 취소·폐쇄 후 내부 데이터의 보관 또는 삭제 방법을 정합니다. 대화 조회는 매번 참가한 시점 이후로 확정했습니다.

  2. 추억 기록의 첫 버전 범위

    프로필 입력 항목, 사진 수·크기, 기록 날짜·메모, 수정·삭제, 기념일 계산 규칙을 구체화합니다. 앨범·태그·영상·공개 범위의 포함 여부도 결정합니다.

  3. 플랫폼·기술·완성 기준

    웹·모바일 범위, 기술 스택, 무료 운영 환경, 제출 결과물과 완료 기준, 주당 참여 시간과 중간 일정을 정합니다.

07

운영·협업 방향

클라우드·운영 영역

한 팀원이 서버·클라우드 포트폴리오를 원합니다. 구체적인 역할 배치는 아직 확정하지 않았습니다.

  • 서비스 실행·배포 환경
  • DB·사진 저장 환경
  • 환경 변수와 비밀값 관리
  • 배포 자동화, 상태·오류 로그
  • 백업·복구, 무료 한도·비용 관리

상세 범위는 운영 PRD로 구체화합니다. 유료 클라우드 자원을 전제로 결정하지 않습니다.

영역이 달라도 맞춰야 할 정보

화면과 백엔드는 각 기능 담당자가 함께 구현할 수 있습니다. 클라우드 담당자가 모든 서비스 로직을 맡는 구조로 고정하지 않습니다.

  • 로그인 사용자와 반려동물 식별 방법
  • 참가 상태와 채팅 접근 권한
  • 데이터 구조와 변경 절차
  • 요청·응답 형식, 날짜·시간 기준
  • 파일 저장·배포·완료 확인 방법

공통 규칙과 담당 영역 PRD를 함께 전달합니다.

담당 배분 원칙
먼저 만들 기능과 구현 깊이를 정리하고, 연결 관계와 작업량을 보고 영역을 묶습니다. AI가 생성한 코드도 실제 동작과 연결 상태를 확인한 뒤 완료로 처리합니다.
